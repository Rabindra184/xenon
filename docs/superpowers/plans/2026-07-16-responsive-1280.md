# Responsive 1280 Floor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Guarantee the Xenon dashboard renders with nothing clipped between 1280px and 1440px, and add a Playwright guard that keeps it that way.

**Architecture:** A dev-only seed script gives the layouts real content (empty tables cannot clip, so an unseeded guard passes vacuously). A Playwright spec then loads each route at a set of widths — including both sides of every breakpoint boundary — and asserts no element's right edge exceeds the viewport. Only then do we fix the one confirmed break. The guard must fail first; a guard that has never failed proves nothing.

**Tech Stack:** React 17 + Vite + Tailwind, Playwright (new devDep in `web/`), Prisma 5.4 + SQLite, TypeScript 5.5.

**Spec:** `docs/superpowers/specs/2026-07-16-responsive-1280-design.md`

## Global Constraints

- **Supported range is 1280–1440 only.** Do not add phone/tablet-portrait support, a hamburger, or a drawer. Do not touch the sidebar's fixed `w-14` (56px) rail.
- **Never measure `document.scrollWidth` to detect overflow.** `index.css:32` sets `body { overflow: hidden }`, which forces `scrollWidth === innerWidth`. Overflow reads as zero while content is silently clipped. Measure element `getBoundingClientRect().right` against `window.innerWidth`.
- **Actions stay visible at every supported width.** Never fix a clip by hiding controls (`display: none`) or by adding `overflow: hidden` to mask it. Fix the cause.
- **Breakpoint convention: Tailwind mobile-first `min-width` only.** Tailwind defaults: `sm`=640, `md`=768, `lg`=1024, `xl`=1280, `2xl`=1536.
- **Out of scope, do not "fix":** Selector Health's 9-col table (1146px intrinsic floor — fits at 1280), its 7-col timeline (678px), and `build-list-rail.tsx:64`'s `w-[280px]` (leaves 944px at 1280). All verified fitting.
- **The 1025–1145px dead zone is out of scope.** Below the 1280 floor. Documented in the spec.
- **Seed script must never run on boot** and must never default to `~/.cache/xenon/xenon.db`. Require an explicit `DATABASE_URL`.

## The confirmed bug (measured, not theorised)

Measured live at 1280×800 against a running 1.7.0 server with a real Android attached:

```
.control-view-main       width 1280, padding 24px, gap 32px, justify-content: center
  available for columns  = 1280 - 48 (padding) - 32 (gap) = 1200px
.device-preview-column   width 829px   flex: 0 0 auto  (flex-shrink: 0)  min-width: 400px
.device-interactions-column  width 450px  flex: 1 1 0%  min-width: 450px
  needed = 829 + 450 = 1279  >  1200 available
```

The preview column is **829px** even though the phone inside it is only **381px**. The culprit is its sibling:

```
.device-footer-actions   <aside>  829px  display:flex  flex-wrap: nowrap (default)  11 children
```

11 toolbar buttons (PORTRAIT/LANDSCAPE/HOME/BACK/APPS/VOL+/VOL−/lock/unlock/…) in a non-wrapping flex row give it an **829px min-content width**. Because `.device-preview-column` is `flex-shrink: 0`, the column inflates to its widest child. Total content = 829 + 32 + 450 = 1311 vs 1232 inner width → **79px of overflow**, split ~39.5px onto *each* side by `justify-content: center` (so it clips left *and* right; the left clip is invisible under `overflow: hidden`).

`device-control.css:1291`'s `@media (max-width: 900px)` already stacks the layout — but nothing applies at 1280.

**Verified non-causes (do not chase):** viewport height (column stays 829px at both 800 and 1100 height); the phone image (351×766); the `min-width: 400px`/`450px` values (400+450=850 < 1200 and would fit fine).

**Schema facts (verified against `prisma/schema.prisma`, do not re-derive):**
- `model Device` (`:135`) has a **composite primary key**: `@@id([udid, host])`. An upsert must use `where: { udid_host: { udid, host } }`, not `where: { udid }`.
- `Device` has **no `osVersion` field**. The OS version column is `sdk` (`String?`, default `"unknown"`).
- Only `udid` and `host` are required. Everything else is optional or defaulted.
- `model LocatorEtalon` (`:226`) requires `selector` (`@unique`), `strategy`, `attributes`, `nodeName`. It has **no `healCount`** field.

- [ ] **Step 3: Write minimal implementation**

Create `src/scripts/seed-dev-data.ts`:

```typescript
/**
 * Dev-only seed data. Populates realistic, deliberately hostile content so the
 * layouts have something to clip on — empty tables cannot clip, so a guard run
 * against an unseeded database passes vacuously.
 *
 * Never runs on boot. Requires an explicit DATABASE_URL so it can never be
 * pointed at a real ~/.cache/xenon/xenon.db by accident.
 */
import { PrismaClient } from '../generated/client';

export interface SeedDevice {
  udid: string;
  /** Required: Device's primary key is @@id([udid, host]). */
  host: string;
  name: string;
  platform: string;
  /** Device has no `osVersion` column — the OS version lives in `sdk`. */
  sdk: string;
  deviceType: string;
}

const HOST = '127.0.0.1';

export function buildSeedDevices(): SeedDevice[] {
  return [
    { udid: 'SEED-DEVICE-01', host: HOST, name: 'Pixel 8 Pro — Bangalore Lab Rack 4 Slot 12', platform: 'android', sdk: '14', deviceType: 'real' },
    { udid: 'SEED-DEVICE-02', host: HOST, name: 'Samsung Galaxy S24 Ultra — Munich Lab Rack 2', platform: 'android', sdk: '14', deviceType: 'real' },
    { udid: '00008110-00084CE80E51401E', host: HOST, name: 'iPhone 15 Pro Max — Regression Pool Primary', platform: 'ios', sdk: '26.5.2', deviceType: 'real' },
    { udid: '00008120-001A45D40A88802E', host: HOST, name: 'iPad Pro 12.9 — Tablet Matrix Coverage Device', platform: 'ios', sdk: '17.4', deviceType: 'real' },
    { udid: 'SEED-DEVICE-05', host: HOST, name: 'OnePlus 12 — Performance Benchmarking Handset', platform: 'android', sdk: '14', deviceType: 'real' },
    { udid: 'SEED-DEVICE-06', host: HOST, name: 'Xiaomi 14 Ultra — Localisation Test Device APAC', platform: 'android', sdk: '14', deviceType: 'real' },
  ];
}

export async function seed(): Promise<void> {
  if (!process.env.DATABASE_URL) {
    throw new Error(
      'seed-dev-data: refusing to run without an explicit DATABASE_URL. ' +
        'This script writes test rows and must never touch a real database by default. ' +
        'Example: DATABASE_URL="file:/tmp/xenon-seed.db" npm run db:seed',
    );
  }
  const prisma = new PrismaClient();
  try {
    for (const d of buildSeedDevices()) {
      await prisma.device.upsert({
        // Composite key: @@id([udid, host]) -> the compound selector is udid_host.
        where: { udid_host: { udid: d.udid, host: d.host } },
        update: { name: d.name, platform: d.platform, sdk: d.sdk },
        create: {
          udid: d.udid,
          host: d.host,
          name: d.name,
          platform: d.platform,
          sdk: d.sdk,
          deviceType: d.deviceType,
          state: 'available',
          busy: false,
          offline: false,
        },
      });
    }
    console.log(`[seed] devices: ${buildSeedDevices().length}`);
  } finally {
    await prisma.$disconnect();
  }
}

if (require.main === module) {
  seed().catch((e) => {
    console.error(e.message);
    process.exit(1);
  });
}
```

Selector Health's 9-col grid has a 1146px intrinsic floor and therefore **fits at 1280** — it is listed in the spec as verified-fitting, so seeding it is defensive rather than load-bearing, and `LocatorEtalon` is not obviously the table the page reads (it has no heal-count column). Create `web/test/viewport/overflow.spec.ts`:

```typescript
import { test, expect } from '@playwright/test';

/**
 * Supported range is 1280-1440. Widths include BOTH SIDES of every breakpoint
 * boundary — that is the specific mechanism that catches a breakpoint set below
 * a layout's intrinsic minimum, which is the bug class this guard exists for.
 * (Selector Health shipped a max-width:1024 override 121px below its own 1146px
 * floor, leaving a dead zone at 1025-1145 invisible from either end.)
 */
const WIDTHS = [1280, 1281, 1399, 1400, 1440];

const ROUTES = [
  '/xenon/overview',
  '/xenon/devices',
  '/xenon/builds',
  '/xenon/apps',
  '/xenon/selector-health',
  '/xenon/settings',
  '/xenon/teams',
  '/xenon/users',
  '/xenon/api-keys',
  '/xenon/maintenance',
  '/xenon/notifications',
  '/xenon/ai-settings',
  '/xenon/devices/SEED-DEVICE-01/control',
];

for (const width of WIDTHS) {
  for (const route of ROUTES) {
    test(`no overflow at ${width}px on ${route}`, async ({ page }) => {
      await page.setViewportSize({ width, height: 900 });
      await page.goto(route);
      await page.waitForLoadState('networkidle');

      // body{overflow:hidden} forces scrollWidth === innerWidth, so document
      // scroll CANNOT detect this. Measure element rects.
      const offenders = await page.evaluate(() => {
        const vw = window.innerWidth;
        return Array.from(document.querySelectorAll('body *'))
          .map((el) => {
            const r = el.getBoundingClientRect();
            return { el, right: r.right, width: r.width };
          })
          .filter((x) => x.right > vw + 1 && x.width > 0)
          .sort((a, b) => b.right - a.right)
          .slice(0, 5)
          .map((x) => ({
            tag: (x.el as HTMLElement).tagName,
            cls: ((x.el as HTMLElement).className || '').toString().slice(0, 60),
            overflowPx: Math.round(x.right - vw),
          }));
      });

      expect(
        offenders,
        `Elements escape the viewport at ${width}px on ${route}:\n` +
          offenders.map((o) => `  ${o.tag}.${o.cls} overflows by ${o.overflowPx}px`).join('\n'),
      ).toEqual([]);
    });
  }
}
```

```css
.device-footer-actions {
  display: flex;
  /* 11 buttons in one non-wrapping row give this a ~829px min-content width,
     which inflates .device-preview-column (flex-shrink: 0) far past the 381px
     phone it wraps and pushes the interactions column off-screen at 1280.
     Wrapping lets the column collapse to the preview's real width. */
  flex-wrap: wrap;
  justify-content: center;
  width: 100%;
  background: rgba(15, 23, 42, 0.8);
  backdrop-filter: blur(10px);
  border-radius: 16px;
  border: 1px solid rgba(255, 255, 255, 0.08);
  padding: 6px;
  gap: 6px;
  box-shadow:
    0 10px 25px -5px rgba(0, 0, 0, 0.4),
    0 0 15px rgba(16, 185, 129, 0.05);
}
```

Do **not** fix this by adding `overflow: hidden`, by hiding buttons, or by lowering the `min-width` values — all 11 controls must stay reachable at every supported width, and 400+450=850 already fits within the 1200px available. The min-widths are not the cause.

- [ ] **Step 1: Understand the current pair of rules**

Two rules interact. The base at `apps.css:9`:

```css
.apps-registry-content {
  flex: 1;
  overflow-y: auto;
  padding: 0 24px 24px;      /* <- the WIDE (>1400px) padding */
  background: var(--bg);
}
```

and the override at `apps.css:498`:

```css
@media (max-width: 1400px) {
  .apps-registry-content {
    padding: var(--space-4) 24px;   /* <- the NARROW (<=1400px) padding */
  }
}
```

So today: **≤1400 → `var(--space-4) 24px`**, **≥1401 → `0 24px 24px`**. The narrow rule fires across most of the supported band (1280–1400). Note the two are not merely different spacing — the narrow one adds top padding the wide one omits.

- [ ] **Step 2: Invert to min-width, preserving behaviour exactly**

Narrow becomes the base; wide becomes the `min-width` enhancement. The breakpoint moves from `max-width: 1400` to `min-width: 1401` so the same widths get the same padding.

Edit `apps.css:9` to make the narrow padding the base:

```css
.apps-registry-content {
  flex: 1;
  overflow-y: auto;
  padding: var(--space-4) 24px;
  background: var(--bg);
}
```

Replace the `apps.css:498` block with:

```css
/* Wide screens drop the top padding; the header already provides the gap.
   Mobile-first min-width only — see CLAUDE.md. Was max-width: 1400px. */
@media (min-width: 1401px) {
  .apps-registry-content {
    padding: 0 24px 24px;
  }
}
```

Supported range is **1280–1440** (laptop + tablet landscape). No phone or
tablet-portrait support: no hamburger, no drawer. The sidebar is a fixed 56px

vacuously.

always equals `innerWidth`. It cannot detect overflow. Measure element rects.
